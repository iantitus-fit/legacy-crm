# Sprint 14.5: Dashboard UX + Navigation Labels — Design

**Date:** 2026-04-11
**Scope:** 7 features driven by client tester (Marcus) feedback. One backend migration. Global FAB. Dashboard task sections. Pipeline button label fixes. Estimates list create button. Responsive estimate detail. Estimate name + header metadata. Clickable tel/maps links everywhere.

## Findings From Exploration

- Estimate `name` column already exists (surprise). Only `expiration_date` and `created_by_user_id` are new.
- Contacts has no `company` column — need to add one.
- Dashboard stats endpoint already returns `tasks_due_today` and `tasks_due_this_week`; need to add `tasks_past_due` and split "future" from "this week".
- `Layout.jsx` is the global injection point for the FAB. `AppointmentModal` is already reusable. Tasks currently have no standalone create modal (only via `JobTasksTab`).
- Latest migration is `0016_payments.py` → new one is `0017`.

## Feature 1 — Dashboard Task Rows

Replace the "Getting Started" block with a 3-column grid (or stacked rows on mobile): **Past Due**, **Today**, **Future**. Each shows up to 5 tasks with title, linked job/contact, due date, assignee initial, and a count badge. Clicking a task row navigates to its parent job (or tasks list if no job). "View all" link at the bottom of each column routes to `/tasks`.

**Backend:** extend `GET /api/dashboard/stats` to return three new fields: `tasks_past_due`, `tasks_today`, `tasks_future`. Each is `List[TaskDueResponse]` limited to 5 items, ordered by due_date. Keep the existing fields for backward compatibility but the frontend will use the new ones.

- `tasks_past_due`: due_date < today, status = "open", limit 5 oldest-first.
- `tasks_today`: due_date == today, status = "open", limit 5.
- `tasks_future`: due_date > today, status = "open", limit 5 soonest-first.

**Frontend:** delete the Getting Started section. Build a new `DashboardTaskSection` component rendering one column. The DashboardPage renders three.

## Feature 2 — Floating Quick-Create FAB

Global FAB in `Layout.jsx`. Round amber button bottom-right, `fixed` position, z-index above content. Click toggles a menu above the FAB with 4 options:

- **New Lead** → opens `QuickCreateLeadModal` (new)
- **New Estimate** → opens `JobPickerModal` (new) → on selection, POSTs new estimate for that job, navigates to `/estimates/{id}`
- **New Appointment** → mounts existing `AppointmentModal` directly
- **New Task** → opens `QuickCreateTaskModal` (new)

All modals are mounted at the FAB component level so they're available globally. Menu closes on outside click and after a selection.

**Don't show on:** the customer portal routes (`/portal/...` etc.) which are outside the authed Layout anyway.

## Feature 3 — Pipeline Button Labels

`PipelineBoardPage.jsx` has one "+ Add Job" button. Switch to a pipeline-slug-aware label + handler:

| Slug | Label | Handler |
|------|------|---------|
| `leads` | + Add Lead | Opens `QuickCreateLeadModal` |
| `sales` | + New Estimate | Opens `JobPickerModal` |
| `jobs` | + Add Job | Existing behavior (navigates to `/jobs`) |

Reuses the shared modals from the FAB.

## Feature 4 — "Create Estimate" on Estimates List

`EstimatesPage` header gets a "+ Create Estimate" button. Also shown in the empty state. Opens `JobPickerModal` (same flow as FAB and Sales Pipeline button).

## Feature 5 — Responsive Estimate Detail

The page currently has fixed-width columns (`w-20`, `w-28` on qty/price/total) plus a 1280-ish min-width effect from many absolutely-sized elements. Fix by:

- Removing horizontal overflow on the main container. Set `overflow-x-auto` only on the line-items list wrapper, not the page body.
- Shrinking fixed widths for qty/price/total to `w-16`/`w-24` at default and wrapping the hover icons into a single flex gap.
- Letting the description column use `min-w-0 truncate` so long product names ellipsize.
- Constraining the totals panel and change order cards to `max-w-full`.
- Mobile (<640px): stack the columns, hide qty/price columns behind a toggle, show only description + line total.

## Feature 6 — Estimate Name + Header Metadata

**Backend (migration 0017_sprint14_5):**
- `estimates.expiration_date DATE NULL`
- `estimates.created_by_user_id INT NULL FK users(id)`
- `contacts.company VARCHAR(255) NULL`

**Backend (schemas + routers):**
- `EstimateCreate` and `EstimateUpdate` get optional `name`, `expiration_date`, `created_by_user_id` (created_by set server-side only).
- `EstimateResponse` adds `expiration_date`, `created_by_user_id`, `created_by_user_name`, plus nested `contact_company`, `contact_phone`, `contact_email` computed fields.
- `create_estimate` sets `created_by_user_id = current_user.id`.
- `ContactResponse` adds `company`.
- `ContactUpdate` / `ContactCreate` accept `company`.

**Frontend:**
- Redesign the header panel on `EstimateDetailPage.jsx`: two-column layout (left = customer info, right = estimate metadata).
  - Left column: company name (if set), contact name, address, phone (clickable), email (mailto), property address.
  - Right column: estimate number (e.g., "Estimate #ID"), created date, expiration date (editable inline), salesperson.
- Inline name edit already exists. Inline expiration_date edit: text input with `type="date"` that saves on blur.
- Customer portal HTML template (`estimate_public.html` or whatever renders the portal) — add expiration_date row.
- `estimate_pdf.html` — add expiration_date row to the header area.
- `ContactDetailPage`: add company field to the form.

## Feature 7 — Clickable Phone & Address

New shared components:
- `frontend/src/components/PhoneLink.jsx` — renders `<a href="tel:+1XXXXXXXXXX">{formatted}</a>`. Strips non-digits from the href; keeps caller-supplied display text.
- `frontend/src/components/AddressLink.jsx` — renders `<a href="https://maps.apple.com/?q={encoded}" target="_blank" rel="noreferrer">{display}</a>`.
- Both handle null/empty by rendering a dash.

**Replace text in:**
- `ContactDetailPage.jsx` (phone + address display)
- `ContactsPage.jsx` (phone cell in list table)
- `JobDetailPage.jsx` (phone, email display — use mailto for email)
- `AppointmentModal.jsx` (phone in contact picker)
- `JobCard.jsx` (address)
- `PipelineBoardCard.jsx` (address)
- `EstimateDetailPage.jsx` (new header fields added in Feature 6)
- `InvoiceDetailPage.jsx` (header)
